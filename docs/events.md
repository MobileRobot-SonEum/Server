# 이벤트 기록 형식 (현장 규칙 엔진 → 에이전트 서버)

> - **이 서버가 하는 일**: 규칙 엔진이 보낸 이벤트 기록을 저장하고, 해제되면 사고 보고서 초안과 부모 알림 문구(교사 승인 대기)를 만듭니다.
> - **하지 않는 일**: 넘어짐 판정, 현장 응급 알림 전송, 영상·좌표 처리는 하지 않습니다(모두 규칙 엔진 담당).
> - **교사 알림**: 이 서버가 보내는 교사 알림은 **아이 대화(temi)에서 생긴 것만**입니다. 넘어짐 같은 현장 응급 알림과는 별개입니다.

> 상태: **초안 v0.1 (2026-11-13)**. 현장 규칙 엔진 담당과 합의 전입니다. 바꾸고 싶은 점은 이 문서에 바로 적어 주세요.

## 역할 나눔

- **현장 규칙 엔진**(현장 노트북)이 넘어짐 같은 사건을 판정하고, 교사 알림을 **직접, 바로** 보냅니다.
- **에이전트 서버**는 그 기록을 받아 저장하고 **사고 보고서 초안**과 **부모 알림 문구 초안**(교사 승인 대기)을 만듭니다. 판정이나 알림은 하지 않습니다.
- 그래서 에이전트 서버가 꺼져 있거나 느려도 응급 대응에는 영향이 없어야 합니다. 규칙 엔진은 이 API 호출이 실패해도 알림 흐름을 멈추지 말고, 나중에 다시 보내 주세요(아래 '재전송' 참고).

## 엔드포인트

```
POST /events
X-API-Key: <RULE_ENGINE_API_KEY>
Content-Type: application/json
```

## 필드

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `event_id` | string | ✔ | 이벤트 한 건의 고유 ID. 규칙 엔진이 만듦(UUID 권장). **같은 ID로 다시 보내면 중복 저장하지 않음** |
| `incident_id` | string | ✔ | 같은 사건의 감지·알림·해제를 묶는 ID. 감지 때 규칙 엔진이 만들고 이후 이벤트에 그대로 씀 |
| `type` | string | ✔ | 사건 종류. 지금은 `fall`(넘어짐). 늘어나면 이 표에 추가 |
| `phase` | string | ✔ | `detected`(감지) / `alerted`(교사 알림 보냄) / `resolved`(해제) |
| `timestamp` | string | ✔ | 이 이벤트가 일어난 시각. ISO 8601, **시간대 포함** (예: `2026-11-13T11:52:03+09:00`) |
| `location` | string |  | temi 위치 이름 또는 카메라 구역 이름 (예: `놀이방`) |
| `confidence` | number |  | 0~1. 감지 신뢰도 (`detected`에서 권장) |
| `source` | string |  | 감지 방법·장치 (예: `mediapipe_pose:cam-playroom`, `temi_camera`) |
| `alert_channels` | string[] |  | `alerted`에서 알림을 보낸 경로 (예: `["teacher_app", "temi_speaker"]`) |
| `resolved_at` | string | `resolved`면 ✔ | 해제 시각 (ISO 8601) |
| `resolved_by` | string | `resolved`면 ✔ | 해제한 사람 (예: `햇살반 담임`, 교사 ID). 아이 이름은 넣지 않음 |
| `resolution_method` | string |  | `voice`("테미, 괜찮아") / `app` / `timeout` |
| `child` | string \| null |  | 아이를 특정한 경우만. 보통은 비움(null) |
| `note` | string |  | 규칙 엔진이 남기는 짧은 메모 (선택) |

- 알 수 없는 필드는 무시합니다(규칙 엔진이 먼저 필드를 늘려도 서버가 깨지지 않음).
- 영상, 사진, 몸 좌표 같은 원본 데이터는 보내지 않습니다. 텍스트 기록만 받습니다.

## 예시: 넘어짐 → 교사 알림 → "테미, 괜찮아"로 해제

```json
{"event_id": "8f1c…01", "incident_id": "inc-20261113-115203", "type": "fall", "phase": "detected",
 "timestamp": "2026-11-13T11:52:03+09:00", "location": "놀이방", "confidence": 0.91,
 "source": "mediapipe_pose:cam-playroom"}
```
```json
{"event_id": "8f1c…02", "incident_id": "inc-20261113-115203", "type": "fall", "phase": "alerted",
 "timestamp": "2026-11-13T11:52:05+09:00", "alert_channels": ["teacher_app", "temi_speaker"]}
```
```json
{"event_id": "8f1c…03", "incident_id": "inc-20261113-115203", "type": "fall", "phase": "resolved",
 "timestamp": "2026-11-13T11:53:40+09:00", "resolved_at": "2026-11-13T11:53:40+09:00",
 "resolved_by": "햇살반 담임", "resolution_method": "voice"}
```

## 응답

```json
// 201 Created (새 이벤트)
{"event_id": "8f1c…03", "incident_id": "inc-20261113-115203", "duplicate": false,
 "report_id": 12, "approval_id": 34}
```
- `report_id`, `approval_id`는 `resolved` 이벤트에서만 옵니다(자동 생성된 보고서 초안과 부모 알림 승인 대기 건).
- 같은 `event_id`를 다시 보내면 `200`과 `"duplicate": true`를 돌려주고 아무것도 새로 만들지 않습니다.
- 형식 오류는 `422`, 키 오류는 `401`/`403`.

## 재전송

- 네트워크 오류나 5xx면 같은 본문(같은 `event_id`)으로 다시 보내면 됩니다. 중복 저장되지 않습니다.
- 순서가 바뀌어 `resolved`가 `detected`보다 먼저 와도 저장은 됩니다. 보고서에는 그때까지 받은 기록만 쓰고, 빠진 항목은 `[교사 확인 필요]`로 남깁니다.

## 해제되면 서버가 만드는 것

1. **사고 보고서 초안** (상태: `draft`). 이벤트 기록에 있는 사실만 씁니다.
   ```
   사고 보고서 (초안) — inc-20261113-115203
   - 발생 시각: 2026-11-13 11:52:03
   - 장소: 놀이방
   - 감지 방법: mediapipe_pose:cam-playroom (신뢰도 0.91)
   - 교사 알림: 11:52:05 (teacher_app, temi_speaker)
   - 교사 확인(해제) 시각: 11:53:40, 햇살반 담임, 음성 해제
   - 대응 경과: 11:52:03 감지 → 11:52:05 알림 → 11:53:40 교사 확인
   - 대상 아이: [교사 확인 필요]
   - 다친 정도: [교사 확인 필요]
   - 원인·상황: [교사 확인 필요]
   - 조치 내용: [교사 확인 필요]
   ```
2. **부모 알림 문구 초안** (승인 대기). 교사가 아이를 지정하고 승인해야 전송됩니다.
   > 11:52 놀이방에서 넘어짐이 감지되었고, 11:53 선생님이 확인했습니다. 자세한 내용은 선생님이 따로 안내드리겠습니다.

- 같은 사건에 해제 이벤트가 또 오면(다른 `event_id`) 보고서는 새 버전으로 다시 만들고(이전 버전은 `superseded`), 부모 알림은 새로 만들지 않습니다.
- 교사는 에이전트에게 "보고서 다시 만들어 줘"라고 해서 보고서를 다시 만들 수 있습니다(`draft_incident_report`, `incident_id` 또는 `event_id`).

## 참고: 이 서버의 교사 알림 (`/alerts`)과의 차이

| | 현장 응급 알림 | 이 서버의 교사 알림 |
| --- | --- | --- |
| 원인 | 넘어짐 등 영상 판정 | 아이가 temi에게 한 말 ("아파", "때렸어", "엄마 보고 싶어" 등) |
| 보내는 쪽 | 현장 규칙 엔진 | 에이전트 서버 (`TeacherNotifier`, 지금은 스텁) |
| 즉시 전송 | 예 | 긴급 등급만 즉시 전송, 정서 등급은 저장만 (교사 앱이 `GET /alerts`로 조회) |

규칙 엔진은 이 서버의 `/alerts`를 쓰지 않습니다.
